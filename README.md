# 근태·연차관리

직원별 근태를 기록하고 연차 잔여일을 자동으로 계산하는 **단일 HTML 파일** 웹 프로그램입니다.
`index.html` 한 개로 동작하며, 로그인한 사람만 화면을 볼 수 있습니다.

## 주소

- 웹에서 바로 쓰기: **https://hanseong1007.github.io/attendance-app/**
- 파일로 쓰기: `index.html`을 브라우저(휴대폰·PC)로 열어도 똑같이 동작합니다.

## 로그인

1. 처음 열면 로그인 화면이 나옵니다. 관리자 계정은 **아이디 `admin` / 처음 비밀번호 `admin1234`** 입니다.
2. 로그인한 뒤 오른쪽 위 **관리자** 칩 → **내 계정**에서 비밀번호를 바꿔 주세요. (4자 이상)
3. 첫 화면에는 아이디·비밀번호 안내를 띄우지 않습니다. 위 값은 관리자에게만 전달되는 처음 값입니다.

## 처음 쓰기

1. 첫 로그인에서 예시 직원 4명과 샘플 근태 기록이 들어 있습니다.
2. **직원·연차** 탭에서 실제 직원을 추가하고, 예시 직원은 지웁니다.
3. **데이터 → 모두 비우기**를 누르면 예시를 한 번에 지우고 빈 상태로 시작합니다. (되돌릴 수 없으니 필요한 자료는 먼저 JSON으로 백업)
4. **근태 입력**을 눌러 직원·날짜·상태를 고르고 저장합니다. 출근 시각은 **08:30**, 퇴근 시각은 **17:30**이 기본으로 채워집니다. 반차(오전)는 08:30~13:00, 반차(오후)는 13:00~17:30으로 채워집니다.

## 기능

| 구분 | 내용 |
| --- | --- |
| 로그인 | 아이디·비밀번호 로그인, 로그인 유지, 로그아웃, 비밀번호 변경 |
| 계정 관리 | 관리자 전용 **사용자 관리**(계정 추가·비밀번호 재설정·삭제), **초대 링크 복사**로 다른 기기에 계정 옮기기 |
| 직원 관리 | 추가·수정·삭제(이름, 직급, 부서, 입사일, 연차 부여 방식·일수) |
| 연차 부여 방식 | **자동(입사일 기준)** · **자동(연도 기준)** · **수기 입력** 중 선택. 자동은 기준연도를 바꾸면 다시 계산되고, 표·카드에 `입사일자동`/`연도자동`/`수기` 배지가 붙습니다 |
| 근태 상태 | 출근, 지각, 조퇴, 외근/출장, 결근, 연차(1일), 반차(오전/오후 0.5일), 병가/공가 + 출근·퇴근 시각 + 메모. 기본 시각은 출근 **08:30** / 퇴근 **17:30** |
| 요약 카드 | 오늘 출근 인원, 휴가·연차 인원, 지각·결근 인원, 전체 연차 소진율 |
| 연차 자동 계산 | 부여 / 사용(연차 1.0 + 반차 0.5) / 잔여를 입력 즉시 계산해 카드·표에 표시. 기준연도별 누적 |

### 연차 부여 방식별 계산 규칙

| 방식 | 계산 |
| --- | --- |
| 자동 · 입사일 기준 | 기준일(올해는 오늘, 그 밖의 연도는 12월 31일) 현재 근속으로 계산. 만 1년 미만은 경과 월수 1일씩(최대 11일), 만 1~3년 미만은 15일, 만 3년 이상은 `15 + ⌊(근속년수 − 1) / 2⌋`일(최대 25일) |
| 자동 · 연도 기준 | 1월 1일 일괄 부여 방식. 입사 당해연도는 입사월~12월 월 1일씩(최대 11일), 입사 다음연도는 전년도 재직일수 비례(`15 × 재직일수 ÷ 그 해 일수`, 0.5일 단위), 그 뒤로는 `연도 − 입사연도 − 1`년을 근속으로 보아 같은 구간식(최대 25일) |
| 수기 입력 | 0~60일 사이에서 직접 입력(0.5일 단위). 예전에 저장한 자료처럼 방식이 없는 직원은 수기로 읽힙니다 |
| 월별 보기 | 연도·월 선택, 직원·상태 필터, 이름·메모 검색 |
| 내보내기 | 엑셀(CSV, UTF-8 BOM — 한글 안 깨짐), JSON 백업 / 불러오기 |
| 저장 | 브라우저 localStorage에 자동 저장. 새로고침·앱 재실행해도 유지 |

## 보안

- **로그인 게이트**: 로그인 전에는 화면·자료가 열리지 않습니다. 화면 소스에도 앱 내용이 그려지지 않습니다.
- **예시 자료 암호화**: 예시 직원 이름과 샘플 기록은 소스에 평문으로 두지 않고 **SHA-256 키 스트림**으로 암호화해 두었습니다. 관리자 비밀번호(또는 초대받은 직원의 비밀번호)로 열쇠를 풀어야만 메모리에 올라옵니다.
- **비밀번호 저장**: 비밀번호 자체가 아니라 계정마다 다른 salt를 붙인 SHA-256 해시만 저장합니다.
- **검색 차단**: `<meta name="robots" content="noindex, nofollow">` 로 검색엔진 수집을 막았습니다.
- **초대 링크**: 관리자만 만들 수 있고, 링크에는 계정 목록과 (그 직원의 비밀번호로 감싼) 예시 자료 열쇠만 담깁니다. 링크를 연 기기에는 관리자 계정이 생기지 않습니다.
- 계정과 자료는 **그 브라우저(기기)에만** 저장됩니다. 서버로 올라가지 않습니다.

## 참고

- 같은 직원·같은 날짜에 기록은 **1건만** 유지됩니다. 다시 저장하면 기존 기록이 수정되어 연차가 두 번 차감되지 않습니다.
- 데이터는 이 브라우저에만 저장됩니다. 휴대폰과 PC를 함께 쓰려면 **데이터 → JSON 백업 저장**으로 파일을 옮겨 **JSON 불러오기** 하세요. (계정은 각 기기의 **초대 링크**로)
- 브라우저 방문 기록/저장 공간을 지우면 계정과 기록이 함께 사라집니다. 중요한 자료는 JSON 백업을 받아 두세요. 관리자 비밀번호를 잊었을 때도 이 방법(기기 자료 초기화)으로만 처음 값으로 돌아갑니다.
- 직원이 비밀번호를 잊으면 관리자가 **사용자 관리 → 비밀번호 재설정**으로 새 비밀번호를 정해 줄 수 있습니다.
- 휴대폰 Chrome에서 **홈 화면에 추가**하면 앱처럼 전체 화면으로 열립니다.
